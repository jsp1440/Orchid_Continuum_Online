### **2. Self-Sustaining Trigger System**

#### **Database Triggers (PostgreSQL)**
```
Julius AI discovers data → writes to julius_ingest_events
  ↓ (TRIGGER 1: Automatic)
Creates pipeline_tasks → sends NOTIFY event
  ↓ (NOTIFY/LISTEN)
Pipeline workers wake up → process tasks → download images
  ↓ (TRIGGER 2: Automatic)
Saves to image_assets → updates orchestration metrics
  ↓ (TRIGGER 3: Automatic)
Orchestrator refills queue → creates more julius events
  ↓ (LOOP CONTINUES FOREVER)
```

**Key Innovation:** Database triggers create a self-perpetuating loop with NO human intervention required!

## 🗄️ Database Schema

### **New Tables Created:**

1. **`julius_ingest_events`** - Discovery events from Julius AI
2. **`pipeline_tasks`** - Auto-generated processing queue
3. **`image_assets`** - Unified image storage with metadata
4. **`orchestration_status`** - System metrics and coverage
5. **`worker_heartbeats`** - Worker health monitoring

### **Triggers Active:**
- ✅ `julius_ingest_trigger` - Creates tasks when Julius discovers data
- ✅ `image_asset_trigger` - Updates metrics when images saved
- ✅ `task_completion_trigger` - Auto-retries failed tasks

### **🔧 Critical Transaction Fix Applied:**
**Issue:** Workers used `ISOLATION_LEVEL_AUTOCOMMIT` but ran `SELECT ... FOR UPDATE SKIP LOCKED`, which psycopg2 forbids (ProgrammingError).

**Solution:** Dual connection architecture:
- `self.conn` (autocommit) - For PostgreSQL LISTEN/NOTIFY
- `self.work_conn` (transactional) - For task processing with FOR UPDATE

**Result:** Workers can now successfully dequeue and process tasks without database errors!

3. **Central Orchestrator** (runs every 60 seconds):

   - Monitors worker heartbeats
   - Restarts dead workers
   - **Creates new julius events to feed the loop**

4. **Loop continues forever** until 100,000 images acquired!

## 🛡️ Safety Features

### **Duplicate Prevention:**
1. **Perceptual Hashing:** MD5 hash of image content
2. **Database Constraints:** UNIQUE constraint on perceptual_hash
3. **Advisory Locks:** Prevent multiple workers from processing same species
4. **Task Deduplication:** UNIQUE constraint on (task_type, scientific_name, status)

### **License Compliance:**
- Only accepts: CC0, CC-BY, CC-BY-SA, Public Domain
- Tracks license and attribution for every image
- Records source URL for citation

### **Worker Recovery:**
- Heartbeat monitoring (2-minute timeout)
- Auto-restart on failure
- Retry logic for failed tasks (3 retries)
- Error logging with stack traces

## 🚨 Troubleshooting

### **Workers Not Starting:**
- Check DATABASE_URL environment variable
- Verify PostgreSQL connection
- Check Python dependencies (psycopg2, requests)

### **No Images Being Downloaded:**
- Check task queue has items: `SELECT COUNT(*) FROM pipeline_tasks WHERE status='queued'`
- Verify workers are listening: Check worker_heartbeats table
- Test API sources: iNaturalist, GBIF, EOL availability

### **Triggers Not Firing:**
- Verify triggers exist: `\df trigger_*` in psql
- Check trigger is attached: `SELECT * FROM pg_trigger`
- Test manually: Insert into julius_ingest_events and check pipeline_tasks
