# 🔐 Culture Sheet Widget - Security Guide

## ⚠️ CRITICAL SECURITY REQUIREMENTS

### **1. Admin Password (REQUIRED)**

**The admin dashboard requires `ADMIN_PASSWORD` environment variable to be set.**

```bash
# In Replit Secrets, add:
ADMIN_PASSWORD=YOUR_STRONG_SECURE_PASSWORD_HERE
```

**Security Requirements:**
- ✅ Minimum 20 characters
- ✅ Mix of uppercase, lowercase, numbers, symbols
- ✅ Unique - don't reuse from other services
- ✅ Store ONLY in environment variables (never in code)

**What Happens if Not Set:**
- ❌ Admin dashboard returns 500 error
- ❌ Cannot toggle demo mode
- ❌ Cannot manage whitelist
- ✅ Widget API continues to work normally (visitor/member limits enforced)

### **2. Neon One API Key**

```bash
# In Replit Secrets:
NEON_ONE_API_KEY=neon_one_org_xxx_yyy
```

**Used for:**
- Verifying membership status
- Checking membership tier (member vs life member)
- Real-time member account lookups

**Fallback Behavior:**
- If API key missing → All users treated as visitors (3 sheets/month)
- If API call fails → Graceful degradation to visitor tier

### **3. Database Access**

**Automatically handled by Replit:**
- `DATABASE_URL` - Set automatically
- PostgreSQL credentials managed by Replit
- No manual configuration needed

### **4. Session Security**

```bash
# In Replit Secrets:
SESSION_SECRET=random_long_string_for_flask_sessions
```

**Purpose:**
- Secure Flask session cookies
- Required by Flask framework
- Auto-generated by Replit

## 🛡️ Security Best Practices

### **Admin Dashboard Access**

**Current Implementation:**
- Simple password-based authentication
- Password sent via HTTP header or query param
- Suitable for internal admin use

**Recommended Enhancements:**
1. **Use HTTPS only** - Replit provides this automatically
2. **IP Whitelist** - Restrict admin access to specific IPs
3. **Rate Limiting** - Prevent brute force attacks
4. **Session-based Auth** - Replace query param auth
5. **Audit Logging** - Track all admin actions

### **API Endpoint Security**

**Current Protection:**
- CORS configured for `*.neoncrm.com` domains
- CSP headers allow iframe embedding from trusted domains
- No CSRF tokens (stateless API by design)
- IP-based visitor tracking (not auth-based)

**Visitor Privacy:**
- IP addresses hashed before storage (recommended)
- Usage data not linked to personal information
- Compliant with privacy regulations

### **Demo Mode Security**

**Risk Assessment:**
- 🟡 **Medium Risk** - Demo mode bypasses all usage limits
- ✅ **Mitigation** - Requires admin authentication
- ✅ **Audit Trail** - All demo mode changes logged with timestamp
- ✅ **Manual Control** - No automatic triggers

**Best Practices:**
1. Enable demo mode ONLY during testing phases
2. Disable after testing complete
3. Monitor usage statistics during demo mode
4. Remove test accounts from whitelist after testing

## 🚨 Security Incident Response

### **If Admin Password Compromised:**

1. **Immediate Actions:**
   ```bash
   # Generate new password immediately
   ADMIN_PASSWORD=NEW_SECURE_PASSWORD_HERE
   ```

2. **Check for unauthorized changes:**
   - Review demo mode status
   - Check whitelist for unknown accounts
   - Review usage statistics for anomalies

3. **Revert unauthorized changes:**
   - Disable demo mode if enabled
   - Remove unknown accounts from whitelist
   - Reset any modified settings

### **If Neon One API Key Compromised:**

1. **Revoke key in Neon One dashboard**
2. **Generate new API key**
3. **Update Replit Secret:**
   ```bash
   NEON_ONE_API_KEY=new_key_here
   ```

### **If Usage Limits Bypassed:**

**Symptoms:**
- Unusually high sheet generation counts
- Visitors generating sheets with AI artwork
- Members exceeding yearly limits

**Investigation:**
1. Check if demo mode enabled: `/admin/widget/status`
2. Review whitelist accounts
3. Check database for anomalies:
   ```sql
   SELECT * FROM culture_sheet_usage 
   WHERE sheets_generated > 1000 
   ORDER BY sheets_generated DESC;
   ```

## 📊 Security Monitoring

### **Admin Activity Logging**

All admin actions are logged in `admin_settings` table:
- Who made the change (`updated_by`)
- When it happened (`updated_at`)
- What was changed (`setting_key`, `setting_value`)
- Why it was changed (`description`)

**Example Query:**
```sql
SELECT * FROM admin_settings 
ORDER BY updated_at DESC 
LIMIT 10;
```

### **Usage Anomaly Detection**

**Red Flags:**
- Visitor with >100 sheets/month
- Same IP generating sheets every second
- AI artwork enabled for non-members
- Unusual geographic patterns

**Monitoring Query:**
```sql
-- Find suspicious high usage
SELECT ip_address, neon_one_account_id, 
       sheets_generated, membership_tier
FROM culture_sheet_usage
WHERE sheets_generated > (
  CASE membership_tier
    WHEN 'visitor' THEN 3
    WHEN 'member' THEN 100
    ELSE 50
  END
)
AND last_generation_date > NOW() - INTERVAL '30 days';
```

## ✅ Security Checklist

### **Before Launch:**
- [ ] Set strong `ADMIN_PASSWORD` (20+ characters)
- [ ] Verify `NEON_ONE_API_KEY` is working
- [ ] Test admin dashboard with password
- [ ] Confirm demo mode starts DISABLED
- [ ] Verify whitelist is empty
- [ ] Test CORS headers work for Neon One embedding

### **Monthly:**
- [ ] Review admin activity logs
- [ ] Check demo mode status (should be OFF)
- [ ] Audit whitelist accounts
- [ ] Review usage statistics for anomalies
- [ ] Verify API costs are within budget

### **After Testing:**
- [ ] Disable demo mode
- [ ] Clear whitelist (or keep VIPs only)
- [ ] Review all admin changes
- [ ] Document any permanent whitelist accounts
